---

### How I Work With AI (And Why It Doesn't Produce Slop)
A lot of AI-generated code online is low-quality because people treat LLMs like magic buttons: they type a vague prompt, copy whatever comes out, and have no idea what to do when it breaks. 

I don't work that way. My setup behaves differently because of how I direct it:

- **Strict engineering rules**: I've trained and customized my AI with explicit boundaries. It has to formulate a plan before writing code, trace root causes instead of guessing surface fixes, and stick to clean, maintainable patterns.
- **Backed by systems fundamentals**: My background is in networking—packet analysis in Wireshark, routing topologies in Packet Tracer/GNS3, and firewall rules in pfSense. Because I understand what's happening at the protocol and OS level, I don't just check if code runs; I verify how it behaves against real system state and network traffic.
- **Supervision, not blind trust**: I treat AI like a junior developer on my team. It gives me the velocity to write in languages I'm still exploring, while I inspect the output, catch edge cases, and maintain high standards.
- **Learning beyond code**: Building this way has accelerated my education. I use AI as an intellectual sparring partner to deconstruct new computer science concepts, dive into unfamiliar frameworks, and learn topics completely outside IT.
